Ticket: Operators keep shipping configs where port is a string like "5432x" or timeout is negative, and the service only fails much later with a confusing traceback. Make settings.load validate and coerce: port -> int in 1..65535, timeout -> float > 0, retries -> int >= 0, verbose -> bool from the usual true/false spellings. On a bad value raise SettingsError with a message that names the setting, shows the value it received, and states what was expected. Keep existing behavior for host and for unknown keys.
